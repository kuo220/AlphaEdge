# 回測滑價與執行係數

## Abstract

- **背景／問題**：回測目前直接把策略產生的 `StockOrder.price` 當成交價，沒有任何滑價假設；`TickQuote` 雖有 bid/ask 欄位但僅作資料模型。缺少滑價會系統性高估策略績效，尤其是流動性差或開盤跳空的標的。
- **目標**：在**不新增** `core/execution/`、`core/costs/` 等頂層模組、不重構 `core` 分層的前提下，加入可調整的滑價與執行係數（買／賣方向不同 bps、固定跳價，日後可擴充為依量級調整），並與既有手續費／證交稅計算銜接清楚。
- **範圍界線**：**不做**多市場／多券商費率設定檔載入、不新增頂層資料夾；只滿足單一市場（台股）、全系統或每策略可選參數。
- **註（2026-08-02）**：原範圍界線寫「不做 `CostModel` 抽象與依賴注入」，該項已改由 [多市場回測引擎架構](../docs/backtest/multi-market-engine.md) 負責。本文件維持只做滑價係數本身，但**掛點改為 `FillModel`**，並建議排在多市場抽象之後，避免掛點搬兩次。
- **驗收標準**：滑價係數為 0 時回測結果與改動前逐筆相同；非零時買賣調價方向符合文件敘述；手續費與證交稅以調整後價格計算，且有可重現的範例數字。

## S1. 決定係數存放位置 ⬜

- **目的**：先定案存放位置，後續步驟才有明確的 import 目標。
- **做法**：二選一——
  - **做法 A**：在 `core/utils/constant.py` 新增與 `Commission` 並列的常數區塊（例如 `SlippageDefaults` / `BacktestExecution`），與現有風格一致。
  - **做法 B（推薦，語意分離）**：新增單檔 `core/utils/backtest_execution.py`，以常數或 `dataclass` 存放預設 bps、是否啟用等，避免「法規費率」與「回測假設」混在同一 enum。

  兩者皆**不必**在 `core/` 下新增頂層資料夾。
- **產出**：本文件補上決策段落；以及選定的常數檔案。
- **驗證方式**：決策理由寫入本文件，且與 §2.7 的「常數先定義 module-level `UPPER_SNAKE_CASE` 再由 Enum 引用」慣例一致。
- **相依**：無。

## S2. `StockUtils` 新增調價純函式 ⬜

- **目的**：把「參考價 → 含滑價成交價」的規則收斂成單一純函式，方便測試與日後替換。
- **做法**：於 `core/utils/instrument.py` 的 `StockUtils` 新增靜態方法，依 `Action`／買賣方向對參考價套用 bps。**買進加價、賣出減價的規則需寫死並在註解說明理由**，不要留給呼叫端自行決定符號。
- **產出**：`core/utils/instrument.py`。
- **驗證方式**：買、賣兩個方向各一組單元測試，含 bps 為 0 的邊界（應回傳原價）。
- **相依**：S1。

## S3. `FillModel` 掛點：開平倉前調價 ⬜

- **目的**：讓所有策略共用同一個調價掛點，各策略建立 `StockOrder` 處不必重複改。
- **做法**：於 `core/backtest/backtester.py` 的 `execute_open_signal`、`execute_close_signal` 內，在呼叫 `self.position_manager.open_position` / `close_position` **之前**對每筆 `StockOrder.price` 做調整。需注意不可意外改到策略快取的 order 物件（必要時複製 order）。
  - **優點**：`position_manager` 維持「訂單上的價即成交價」語意，日後接實盤路徑不易分岔。
  - **替代方案（次選）**：在 `position_manager` 入口調價；缺點是模擬假設與部位管理耦合較深。
- **與手續費計算順序**：須明確約定「先得到含滑價的成交價，再以該價進 `StockUtils.calculate_transaction_commission` 等」，使手續費與滑價假設一致，並寫入 S5 的文件。
- **產出**：`core/backtest/backtester.py`。
- **驗證方式**：滑價係數設 0 時，LONG 回歸 baseline 逐筆相同；非零時買入成交價不低於、賣出成交價不高於基準價。
- **相依**：S2。

## S4. （可選）每策略可選參數 ⬜

- **目的**：支援「策略 A 保守、策略 B 不滑價」的實驗需求。
- **做法**：於 `core/strategies/stock/base.py` 的 `BaseStockStrategy` 增加可選欄位（買／賣 bps，`None` 表示用全域預設）；`Backtester` 讀 `self.strategy` 再帶入調價函式。
- **產出**：`core/strategies/stock/base.py`、`core/backtest/backtester.py`。
- **驗證方式**：兩支設定不同 bps 的策略跑出不同成交價；未設定的策略行為與 S3 相同。
- **相依**：S3。此步驟為可選，未做不影響前四步的驗收。

## S5. 文件 ⬜

- **目的**：讓使用者知道預設值、如何關閉、以及與手續費的計算順序。
- **做法**：於 `core/backtest/README.md` 或 `docs/` 簡短說明三件事：預設係數值、如何關閉（設 0）、滑價與手續費的先後順序。主 `README.md` / `README_zh.md` 只加一行連結，避免參數表塞滿首頁。
- **產出**：`core/backtest/README.md`。
- **驗證方式**：人工檢視；文件中的範例數字可由單元測試重現。
- **相依**：S3。
