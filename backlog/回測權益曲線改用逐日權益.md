# 回測權益曲線改用逐日權益

## Abstract

- **背景／問題**：`Backtester.snapshot_daily_equity()` 已於放空框架 Phase 4 完成，會逐日以收盤價盯市產出含未實現損益的權益快照並存成 CSV，但報表的四張圖仍全部以「已實現損益」為時間軸與數值來源，只在平倉當下才有節點，導致 MDD 被低估、權益曲線形狀失真（來源見 [放空回測框架規格](../docs/backtest/short-selling-framework.md) Phase4-1 與 §7.7 註）。
- **目標**：報表在有 `daily_equity` 時一律以逐日權益（mark-to-market）為準繪圖與計算指標，讓 MDD 反映持倉期間的逆勢。
- **範圍界線**：**只接繪圖與指標的資料來源**，不修改 `snapshot_daily_equity()` 的盯市邏輯、不改 `analyzer` 既有函式簽名（本身已支援 `daily_equity`）、不新增績效指標、不處理 benchmark 資料源本身。
- **驗收標準**：LONG 策略的權益曲線節點數等於回測交易日數；留倉放空案例的 MDD 大於改動前；`daily_equity` 為空時四張圖仍能產出且行為與改動前相同。

## 背景：目前的資料流

`snapshot_daily_equity()` 產出的逐日權益存在 `Backtester.daily_equity`，並輸出成 `{strategy_name}_daily_equity.csv`（`core/backtest/backtester.py` 829–833 行）。但四張圖的資料來源是：

| 函式 | 位置 | 目前資料來源 |
|------|------|--------------|
| `plot_balance_curve` | `reporter.py` 387 | `trading_report` 的 `Exit Date` / `Cumulative Balance` |
| `plot_balance_and_benchmark_curve` | `reporter.py` 426 | 同上 |
| `plot_balance_mdd` | `reporter.py` 553 | 同上（589–592 行） |
| `plot_everyday_profit` | `reporter.py` 667 | `trading_report` 的 `Realized PnL` 依 `Exit Date` 分組 |

`analyzer.py` 的 `compute_equity_curve` / `compute_mdd` 已經**可以**吃 `daily_equity`（`analyzer.py` 37–69 行），但 `generate_backtest_report()` 沒把它傳進去。

### 後果

- **MDD 被低估**：持倉期間的逆勢完全不會出現在曲線上，權益只在平倉那天「跳一階」。留倉放空的最大風險正是持倉期間被軋，這條曲線把它整段抹平。
- **權益曲線形狀失真**：沒有交易的日子沒有節點，曲線是折線跳點而非逐日序列。
- **與 benchmark 對比不公平**：benchmark 是逐日價格序列，策略側卻是稀疏的平倉點。
- LONG 策略同樣受害，不只放空。

## S1. `generate_backtest_report()` 把 `daily_equity` 傳給 reporter ⬜

- **目的**：打通資料流，讓 reporter 拿得到逐日權益。
- **做法**：於 `core/backtest/backtester.py` 816 行起的 `generate_backtest_report()`，在呼叫 `plot_*` 之前把 `daily_equity` 交給 reporter（例如新增 `reporter.daily_equity` 屬性）。
- **產出**：`core/backtest/backtester.py`。
- **驗證方式**：跑一次 LONG 回測，確認 reporter 端取到的序列非空且筆數等於交易日數。
- **相依**：無。

## S2. reporter 新增 `get_equity_series()` 統一序列來源 ⬜

- **目的**：把「用逐日權益還是已實現損益」的判斷收斂到單一入口，避免四張圖各判一次。
- **做法**：在 `StockBacktestReporter` 新增內部方法（例如 `get_equity_series()`）：`daily_equity` 有值時回傳 `Date` → `Equity` 的 `pd.Series`；否則由 `trading_report` 組出既有的 `Exit Date` → `Cumulative Balance` 序列。序列前需補一筆 `origin_date` → `init_capital`，與現行 `plot_balance_curve` 393–401 行的做法一致。
- **產出**：`core/backtest/report/reporter.py`。
- **驗證方式**：`daily_equity` 有值／無值兩條路徑各一項單元測試，確認起點節點都存在。
- **相依**：S1。

## S3. 三張權益圖改吃統一序列並標註口徑 ⬜

- **目的**：讓權益曲線、benchmark 對比與 MDD 圖三者口徑一致。
- **做法**：`plot_balance_curve`、`plot_balance_and_benchmark_curve`、`plot_balance_mdd` 改呼叫 `get_equity_series()`；圖表標題或註腳標明採用的口徑（`Realized only` / `Mark-to-market`），避免不同期報表混淆。
- **產出**：`core/backtest/report/reporter.py`。
- **驗證方式**：LONG 策略回測的 `*_balance_curve.png` 節點數等於回測交易日數，而非平倉筆數；留倉放空測試案例的 MDD 大於同案例改動前的值。
- **相依**：S2。

## S4. `plot_everyday_profit` 口徑決策與新增逐日權益變化圖 ⬜

- **目的**：逐日權益的**差分**是「含未實現變動的當日損益」，與現行「已實現損益依平倉日分組」語意不同，不可直接替換。
- **做法**：保留現有 `plot_everyday_profit`（已實現口徑），另新增一張 `everyday_equity_change`（逐日權益差分），兩張圖標題明確標註口徑差異。
- **產出**：`core/backtest/report/reporter.py`。
- **驗證方式**：人工檢視兩張圖並存且語意可區分；已實現口徑那張的數值與改動前完全相同。
- **相依**：S2。

## S5. `analyzer` 呼叫端補傳 `daily_equity` ⬜

- **目的**：讓分析指標與圖表口徑一致，避免報表數字與圖對不上。
- **做法**：`compute_equity_curve` / `compute_mdd` 的呼叫端補傳 `daily_equity`（函式本身已支援，無需修改 `analyzer.py`）。
- **產出**：`core/backtest/backtester.py`。
- **驗證方式**：`analyzer` 算出的 MDD 與 `plot_balance_mdd` 圖上的最低點一致。
- **相依**：S1。
