# 放空回測市場約束補齊

## Abstract

- **背景／問題**：放空回測框架的 Phase 0~4 已於 2026-08 完成並移出 `backlog/`（規格見 [放空回測框架規格](../docs/backtest/short-selling-framework.md)），但其 Phase5-1 的六個延伸項目被明確排除在該次範圍外。其中三項卡在資料源缺口，兩項因會破壞 LONG 回歸保護線或範圍過大而暫緩。引擎目前假設「任何標的隨時都借得到券、留倉不受停券與股利影響」，放空策略的機會數與績效因此被系統性高估。
- **目標**：補上放空回測缺少的市場約束——券源可得性、停券強制回補、股利補償——讓放空策略的機會數與績效不再被系統性高估。
- **範圍界線**：**不做**融資做多槓桿與同標的雙向持倉（兩者暫緩，理由見 S4、S5）；不重寫既有成本模型；SBL 個股議定費率僅列為低優先，不在本次必做範圍。
- **驗收標準**：融券餘額 ETL 可日更且有對應 API；`Backtester` 開倉前會檢核券源並把拒單計入事件統計；報表可量化「因無券源拒單」的次數。

## S1. 融券餘額／信用交易 ETL ✅

- **目的**：補上放空可行性判斷所需的唯一資料缺口；沒有這份資料，引擎只能假設「任何標的隨時都借得到券」。
- **做法**：
  - **資料來源**：
    - TWSE：`MI_MARGN`（`selectType=STOCK`，僅個股，不含 ETF／TDR／封閉式基金），16 欄。
    - TPEX：上櫃股票融資融券餘額（`www.tpex.org.tw/www/zh-tw/margin/balance`），20 欄。
    - 兩者實測自 2013-01-02 起版面未再改制，因此**不需要像 `stock_chip_*` 那樣做改制日期分流**，一律以「欄位位置」重新命名。
  - **落地方式**：沿用既有 `crawlers` / `cleaners` / `loaders` / `updaters` 四層慣例：

    | 層 | 新增檔案 |
    |----|------------------|
    | crawler | `core/pipeline/crawlers/stock_margin_crawler.py` |
    | cleaner | `core/pipeline/cleaners/stock_margin_cleaner.py` |
    | loader | `core/pipeline/loaders/stock_margin_loader.py` |
    | updater | `core/pipeline/updaters/stock_margin_updater.py` |
    | API | `core/api/stock_margin_api.py` |

  - **資料表 `margin` 欄位（18 欄，數量單位一律為張）**：

    | 欄位 | 說明 |
    |------|------|
    | `date`、`stock_id`、`證券名稱` | Primary Key 為 (`date`, `stock_id`) |
    | `融資買進`／`融資賣出`／`融資現金償還`／`融資前日餘額`／`融資今日餘額`／`融資限額` | 融資六欄 |
    | `融券買進`／`融券賣出`／`融券現券償還`／`融券前日餘額`／`融券今日餘額`／`融券限額` | 融券六欄（S2 券源檢核取 `融券今日餘額`） |
    | `資券互抵` | 當日資券相抵張數 |
    | `券資比` | 衍生欄位（%）：`融券今日餘額 / 融資今日餘額 × 100`，融資餘額為 0 時記為 0 |
    | `註記` | 來源網站的處置／變更交易註記（如 `X`、`OX`、`11 C`），空值存為空字串 |

  - 另在 `tasks/update_db.py` 新增 `--target margin`，`core/config.py` 補 `MARGIN_TABLE_NAME`／`MARGIN_DOWNLOADS_PATH`／`DEFAULT_MARGIN_START_DATE`，`core/pipeline/utils/constant.py` 補 `DataType.MARGIN`，`URLManager` 新增 `TWSE_MARGIN_ALL_URL`（`selectType=ALL`，含股票／ETF／TDR／受益證券）與 `TPEX_MARGIN_ALL_URL`（取代已失效的 `TPEX_MARGIN_SUMMARY_URL`），兩市場命名一致。
- **產出**：
  - 新增：`core/pipeline/crawlers/stock_margin_crawler.py`、`core/pipeline/cleaners/stock_margin_cleaner.py`、`core/pipeline/loaders/stock_margin_loader.py`、`core/pipeline/updaters/stock_margin_updater.py`、`core/api/stock_margin_api.py`、`tests/test_stock_margin_cleaner.py`
  - 修改：`core/config.py`、`core/pipeline/utils/constant.py`、`core/pipeline/utils/url_manager.py`、`tasks/update_db.py`
- **驗證方式與實際結果**（2026-08-01）：
  1. **全流程日更**：以暫存 DB 跑 `StockMarginUpdater.update(2026-07-30 ~ 2026-07-31)`，兩日各入庫 1,974 筆（TWSE 1,060 ＋ TPEX 914）。

> **✅ 完成紀錄（2026-08-01）**
> - **偏離原規格 ①**：CLI 參數定為 `--target margin` 而非規格寫的 `--target stock_margin`。原因是既有 target 命名皆為資料類型短名（`chip`、`price`、`tick`），且該值由 `DataType.MARGIN.name.lower()` 推導，另立長名會破壞 `all` / `no_tick` 的自動展開。
> - **偏離原規格 ②**：規格列出的「是否為暫停融資融券標的（處置股、平盤下不得放空註記）」**未取得結構化欄位**。MI_MARGN 與櫃買餘額表只提供文字 `註記`（`X`／`OX`／`11 C` 等混合代碼），沒有可直接判讀的布林旗標；「平盤下不得放空」屬證交所另一份公告清單。本步驟先把 `註記` 原文入庫，是否再接一份公告清單由 S2 決定。
> - **待辦（不影響本步驟驗收）**：2013-01-01 起的歷史回補尚未執行。單日約需 3~5 秒（含反爬 sleep），約 3,300 個交易日估計數小時，需另行執行 `python -m tasks.update_db --target margin`。**注意**：`get_actual_update_start_date()` 以表內最新日為準，故回補必須在表為空時整段跑完，不可先塞近期資料。
> - **沿用既有慣例的已知問題**：`StockMarginLoader.add_to_db()` 比照 `StockChipLoader`，預設不刪除 downloads CSV，重跑時會因 Primary Key 衝突產生 warning（資料不會重複，但 log 會噪音）。此為既有 loader 的共通行為，未在本步驟修改。

## S2. 券源檢核接進回測框架 ✅

- **目的**：讓引擎在券源不足時拒單，並讓「機會數高估的幅度」可被量化。
- **做法**：
  - 資料由 S1 的 `StockMarginAPI` 提供：`get_stock_short_balance(stock_id, date)` 直接回傳當日融券今日餘額（張），查無資料時回傳 `None`（呼叫端須決定「跳過檢核」或「視為不可放空」）；`get_short_balance(date)` 可一次取當日全市場的餘額／限額／券資比／註記。
  - `ShortConstraint`（`core/backtest/models/cost_model.py`）補「可借券張數上限」欄位。
  - ⚠️ **`check_borrowable` 動工前曾是死碼**（2026-08-07 實查）：當時欄位有定義但全專案無呼叫端，設成 `True` 不會生效也不會報錯。本步驟完成後該開關已真正生效。同批的 `allow_below_reference`、`day_trade_whitelist` **至今仍是死碼**（建構期警告防呆由「回測引擎執行真實度補強」S1 提供，該文件 2026-08-15 完成並移出 `backlog/`），接上撮合的追蹤改由本文件 **S7** 承接。
  - `Backtester` 於開倉前檢核：該標的當日融券餘額不足或屬暫停融券標的 → 拒單並計入 `event_counts`（依框架設計原則 §6「不可靜默失敗」，須 log warning）。
  - 報表的事件統計新增「因無券源拒單次數」。
- **產出**：`core/backtest/models/cost_model.py`（`ShortConstraint` 補欄位）、`core/backtest/models/fill_model.py`（開倉前的券源檢核）、`core/backtest/report/reporter.py`。
- **落點說明（2026-08-02）**：券源檢核屬「這張單能不能成交」，與成交價可信度同性質，因此在 [多市場回測引擎架構](../docs/backtest/multi-market-engine.md) 之後應放 `FillModel` 而非引擎本體；若在多市場抽象之前先做，則暫時放 `Backtester.execute_open_signal()`，並於重構時一併搬移。
- **驗證方式**：構造一檔融券餘額為 0 的標的，開倉被拒且 `*_event_report.csv` 出現對應計數；既有 LONG 回歸不受影響。
- **相依**：S1。

## S3. 除權息行事曆與停券日 ✅

- **目的**：一份資料解兩件事——強制回補日與股利補償現金流，兩者原本都被框架簡化掉。
- **做法**：
  - **ETL**：不需另做。除權息交易日、現金股利、配股率已由 `股價還原與除權息調整`（2026-08-15 完成並移出 `backlog/`）建的 `dividend` 表提供，`StockDividendAPI` 直接取用。
  - **停券日推導**（`TwStockDataFeed.build_force_cover_map()`）：

    ```
    融券最後回補日 = 除權息交易日往前推 4 個營業日
    ```

    法規原文是「停止過戶日前 6 個營業日」，停止過戶日 = 除權息交易日 + 2 個營業日，兩者相減即得 4。`dividend` 表只有除權息交易日，故一律以此換算；營業日取自 `price` 表的實際開盤日（新增 `StockPriceAPI.get_trading_days()` ＋ `MarketCalendar.shift_trading_days()`），用曆日相減會在連假整段位移。整場回測只推導一次。
  - **框架側**：`Backtester.execute_bar()` 每根 bar 把「今日回補標的」與「今日除息股利」推給 `SettlementModel`（與既有 `apply_short_balance()` 同一種掛法），再由 `execute_daily_position_check()` 分兩個分支處理。
  - **三個放空管道的適用範圍不同**（本步驟最關鍵的判斷）：

    | 管道 | 除權息停券強制回補 | 除息日股利補償 |
    |------|--------------------|----------------|
    | `MARGIN` | ✅ 計入 `forced_cover_suspended` | 正常情況碰不到（已先被回補） |
    | `SBL` | ❌ 借券不受強制回補約束 | ✅ 扣 `每股現金股利 × 股數` |
    | `DAY_TRADE` | 當日已由 `enforce_day_trade_cover()` 處理完 | 同左 |

    使用者以 `ShortConstraint.force_cover_dates` **手動指定**的日期則不分管道一律適用——引擎不替使用者的政策再加條件。
  - **與價格還原不重複計算**：部位損益一律以未還原的 `quote.close` 盯市，除息跳空仍在帳面損益裡；股利補償扣掉的正是「跳空該歸誰」，兩者相抵後除息本身不產生損益。還原價只用於**訊號**（`adjusted_price`）。
- **產出**：
  - 新增：`tests/backtest/test_short_market_constraints.py`（17 項）
  - 修改：`core/api/stock_price_api.py`、`core/backtest/datafeed/market_calendar.py`、`core/backtest/datafeed/base.py`、`core/backtest/datafeed/tw_stock_datafeed.py`、`core/backtest/models/cost_model.py`、`core/backtest/models/settlement_model.py`、`core/backtest/backtester.py`、`core/backtest/report/reporter.py`、`core/backtest/analysis/analyzer.py`、`core/managers/stock/position_manager.py`、`core/models/stock/position.py`、`core/models/stock/record.py`、`core/models/stock/account.py`、`tests/backtest/conftest.py`、`tests/backtest/make_short_baseline.py`、三份 SHORT 快照
- **驗證方式與實際結果**（2026-08-22）：

- **相依**：無（`dividend` 表已就緒）。

> **✅ 完成紀錄（2026-08-22）**
> - **實作過程修掉的真實 bug**：股利補償最初「除息日扣餘額」＋「平倉時經 `carry_cost` 計入 `realized_pnl`」兩邊都做，同一筆被扣兩次（期末餘額少了整整一筆補償）。修法比照既有的 `entry_cost`：平倉時把攤提到的那一份加回餘額。**刻意不改成 `accrued_borrow_fee` 那種「只在平倉扣一次」**——除息跳空會讓空單當天憑空多出一段未實現獲利，唯有同日的現金流出才能抵銷，否則逐日權益曲線會失真。
> - **偏離原規格**：規格寫「在 `execute_daily_position_check` 內加入兩個分支」，實際的停券判定落在 `check_force_cover()`（由 `check_margin_call()` 呼叫），股利補償則是 `execute_daily_position_check()` 直接呼叫的 `compensate_cash_dividend()`。原因是停券回補與其他三種強制回補（無報價、持有天數、維持率）共用同一個迴圈與 `force_cover_position()`，另拉一層會讓同一筆部位在一根 bar 內被掃兩次。
> - **效能取捨**：停券日推導要掃整段交易日曆，故 `execute_bar()` 只在 `PositionType.SHORT in get_allowed_directions()` 時才向 DataFeed 取這兩份資料。純做多回測連查都不查，LONG 路徑零額外成本。
> - **已知限制（不影響本步驟驗收）**：
>   1. **股東會停券未涵蓋**，需常會／臨時會的停止過戶日行事曆，目前無資料源。推導出的回補日是實際停券日的**子集**，留倉放空的持有天數仍會被高估一部分，`max_holding_days` 保險絲請保留。
>   2. **上市權息並存的標的拆不出現金股利**（`NULL`，2024 年 1184 筆中 85 筆）。本步驟**不猜 0**：記 warning 並計入 `dividend_compensation_unknown`，該筆放空成本會被低估，但報表看得見有幾筆。要根治須另接股利政策資料源。
>   3. `dividend` 表含 ETF／受益證券，推導出的回補日集合會包含這些無融券制度的標的。實務上不會有對應部位，故不另行過濾。

## S4. 融資做多槓桿 ⏸

- **目的**：支援 LONG 路徑的融資槓桿。
- **做法**：於 `StockPositionManager` 的 LONG 分支加入融資成數與利息計提。
- **產出**：`core/managers/stock/position_manager.py`、`core/backtest/models/cost_model.py`。
- **驗證方式**：LONG 回歸 baseline 重產後，差異可完全歸因於槓桿設定。
- **相依**：`LONG 成本口徑收斂`（**已於 2026-08-15 完成並移出 `backlog/`**，多空記帳已共用 `StockCostModel`）。
- **暫緩原因與解除條件**：無資料依賴、技術上可做，但會動到 **LONG 路徑的資金計算**，直接破壞放空框架賴以保護的 LONG 逐筆回歸線。建議排在 LONG 成本模型口徑收斂之後——屆時 baseline 本來就要重產，一次處理較合算。目前也無策略需求；待出現需要槓桿的 LONG 策略時解除。

## S5. 同標的雙向持倉 ⏸

- **目的**：支援同一標的多空並存的市場中性策略。
- **做法**：現行框架在 `open_short_position` 明確拒絕「已有 LONG 部位的標的再開 SHORT」（`position_manager.py` 150 行起）。要支援雙向需要：
  - 完整的 net position 語意（同標的多空並存時的曝險、保證金、維持率如何合計）
  - `StockAccount.check_has_position` 的方向參數語意重新定義
  - FIFO 平倉篩選在同標的雙向下的配對規則
  - 報表分組（同一 `stock_id` 兩個方向的統計如何呈現）
- **產出**：待範圍確定後另立文件。
- **驗證方式**：待定。
- **相依**：無技術前置。
- **暫緩原因與解除條件**：範圍等同再開一個 Phase，且目前無策略需求；待出現同標的多空並存的策略需求時，另開獨立 backlog 而非在本文件展開。

## S7. 平盤下放空限制與可當沖清單接上撮合 ⏸

- **目的**：`ShortConstraint.allow_below_reference`（平盤下放空限制）與 `day_trade_whitelist`／`check_day_tradable()`（每日可當沖清單）目前**有定義、無撮合呼叫端**——設定後不影響任何回測結果，僅靠 `StockCostModel.check_unimplemented_constraints()` 在建構期發出警告防止誤信。原追蹤文件「回測引擎執行真實度補強」於 2026-08-15 完成移出時未涵蓋此兩項，2026-08-15 盤點後改由本文件承接。
- **做法**：
  - `allow_below_reference`：需「警示／處置股清單」資料源（證交所另行公告，非 `margin` 表的 `註記` 欄可直接判讀，見 S1 完成紀錄的偏離 ②）；接上後於 `FillModel` 開倉檢核。
  - `day_trade_whitelist`：需證交所每日可當沖標的公告；`check_day_tradable()` 已有邏輯，缺的是呼叫端與資料。
  - 兩者接上後移除 `check_unimplemented_constraints()` 對應的警告項，並更新 `tests/backtest/test_unimplemented_constraints.py`。
- **產出**：`core/backtest/models/cost_model.py`、`core/backtest/models/fill_model.py`、對應 ETL（視資料源而定）。
- **驗證方式**：構造警示股／非可當沖標的案例，開倉被拒並計入事件統計；`test_unimplemented_constraints.py` 改斷言「不再警告」。
- **相依**：處置股／可當沖清單資料源。
- **暫緩原因與解除條件**：兩者都卡資料源；待確認公告資料可穩定取得（或出現受此限制影響的策略需求）時解除。

## S6. SBL 個股議定費率校正 ⏸

- **目的**：讓熱門空方標的的借券費貼近實際。
- **做法**：`accrue_holding_cost()` 已能逐日以當日收盤價計提借券費，缺的只是「每檔股票的實際議定費率」——現行採統一預設值（框架文件 §3.3），但熱門空方標的實際費率可達 16%，遠高於預設。
- **產出**：`core/backtest/models/cost_model.py` ＋ 費率資料源。
- **驗證方式**：抽樣熱門空方標的，計提費用接近實際借券成本。
- **相依**：借券成交資料源。
- **暫緩原因與解除條件**：資料取得難度高、對多數標的影響有限；待找到可用的借券成交資料源後解除。
