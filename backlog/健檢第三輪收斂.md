## 步驟詳述

### S1. analyzer 四個交易統計補防零除 ✅

- **目的**：`StockBacktestAnalyzer` 的四個交易統計直接除以可能為零的分母，且**沒有任何一個有防護**：

  ```python
  def compute_win_rate(self) -> float:
      return self.compute_num_winning_trades() / self.compute_num_trades()   # 零筆交易 → 炸

  def compute_win_lose_rate(self) -> float:
      return win_cnt / lose_cnt                                              # 零虧損筆數 → 炸

  def compute_profit_factor(self) -> float:
      return profit / loss                                                   # 零虧損金額 → 炸

  def compute_average_return(self) -> float:
      return total_roi / self.compute_num_trades()                           # 零筆交易 → 炸
  ```

- **實證**（2026-09-05，離線、不連 DB）：

  | 情境 | `win_rate` | `win_lose_rate` | `profit_factor` | `average_return` | `average_holding_days` |
  |------|:----------:|:---------------:|:---------------:|:----------------:|:----------------------:|
  | 零筆交易 | **ZeroDivisionError** | **ZeroDivisionError** | **ZeroDivisionError** | **ZeroDivisionError** | `0.0` ✅ |
  | 兩筆全獲利、零虧損 | `1.0` ✅ | **ZeroDivisionError** | **ZeroDivisionError** | `1.85` ✅ | `3.0` ✅ |

- **為什麼確定是疏漏而不是設計**：同一個類別裡的 `compute_average_holding_days()` 開頭就是
  `if not self.trade_records: return 0.0`。作者想到了其中一個，沒想到另外四個。
- **影響範圍（不要誇大）**：`BaseBacktestAnalyzer` 的 class docstring 寫明「Analyzer 供測試與研究驗算指標，
  正式回測輸出走 `report/reporter.py`」，而 **reporter 端已驗證安全**——
  `get_direction_summary()` 的 `len(wins) / len(group)` 走 `groupby`，groupby 不會產生空組，
  且函式開頭有 `if self.trading_report is None or self.trading_report.empty: return pd.DataFrame()`。
  所以這條**不會影響正式回測報表**，踩到的是拿 analyzer 做研究驗算的人：
  「零虧損筆數」在高勝率策略或短區間回測相當常見，而拿到的是一個沒有訊息的 `ZeroDivisionError`。
- **既有測試為什麼沒抓到**：`tests/backtest/test_risk_metrics.py::test_analyzer_metrics_are_none_without_trades`
  只驗了 `compute_sharpe_ratio`／`compute_sortino_ratio`／`compute_volatility` 三個**風險指標**，
  沒有涵蓋這四個**交易統計**。
- **做法**：
  1. 四個方法的回傳型別改為 `Optional[float]`，分母為零時回 `None`。
     **不要回 `0.0`**——`risk_metrics` 模組已經為同一個問題定過調：
     「零筆交易回 None 而不是 0——『沒有資料』與『風險調整後報酬為零』是兩件完全不同的事」。
     勝率 0% 與「沒有交易可算勝率」必須分得開，`profit_factor = 0` 與「從來沒虧過」更是相反的意思。
  2. 同步改 `core/backtest/analysis/base.py` 的四個 `@abstractmethod` 簽章。
  3. `compute_average_holding_days()` 已回 `0.0`，**一併改為 `None`** 以維持同一類別內的一致口徑；
     若改動有呼叫端風險則維持現狀並在 docstring 註明例外。
- **產出**：見進度表。
- **驗證方式**：兩條測試（零筆交易、零虧損筆數），六個統計都不得拋出且回傳值符合上表；
  `./scripts/run_regression.sh` 通過（analyzer 不在回歸線上，預期零影響）。
- **相依**：無。

- **做法**：九個逐一二擇一——
  - **(A) 補測試**：確認它是策略作者會用到的介面，補一條離線或標 `slow` 的測試，
    使其進入前述「有測試的公開介面」那一組；

  判準建議：`get_stock_*` 系列（單檔取區間）與 `get_ex_dividend_dates` 明顯是策略會用的形狀，
  傾向 (A)；`calculate_stock_futures_margin()` 與 `get_last_tick()` 需先確認是否已被別的路徑取代，
  否則傾向 (B)。
- **產出**：見進度表。
- **驗證方式**：重跑本步驟用的 AST 掃描腳本，零呼叫零測試的公開方法為 0 個；`pytest -m "not slow"` 全綠。
